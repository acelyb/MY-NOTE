## 一、QuantaAlpha 是什么(实读 arXiv 2602.07085v3 + GitHub)

### 1.1 一句话定位

LLM 驱动的**轨迹级自进化**因子挖掘框架:把"一次因子挖掘运行"当作一条**轨迹**,用轨迹级**变异**修正坏子步骤、**交叉**重组好片段,配合"假设-表达式-代码"一致性约束与复杂度/冗余控制,自动产出因子池。

### 1.2 方法骨架(实读重点)

- **轨迹表示**:`τ=(s₀,a₀,s₁,a₁,…,sₙ)` 有序序列,奖励 `R(τ)=L(fᵀ(X),y)−λR(fᵀ)`(预测有效性 − 复杂度/新颖性正则)。进化对象是**整条研究轨迹**(含假设/表达式/代码/反馈),不是孤立因子。
- **变异**:先自省定位"最能解释低奖励的子决策节点 k",重写**局部动作**,前缀冻结 → 只改假设/表达式/代码/机制(如换时间尺度、加 regime 条件)。消融:去掉 mutation 退化最大(IC −0.0079)。
- **交叉**:按轨迹奖励选父本,合并"持续贡献高累积奖励的片段"成连贯序列,显式继承已验证血统。
- **一致性约束**:分层 假设 h→语义描述 d→符号表达式 f(AST)→代码 c;**LLM 验证器**检验 h↔d↔f 对齐 + f↔c 忠实性,失败则重写,直到通过或达重试预算。核心动机:"直接代码生成脆弱,有语法错误/依赖不匹配/语义漂移"。
- **复杂度/冗余控制**:`C(f)=α₁SL+α₂PC+α₃log(1+|F|)`;约束 符号长度≤250、基础特征≤6、自由参数比<50%、重复子树≤5。去冗余两段:**结构级**(AST 最大公共子树)+ **功能级**(验证段输出相关>阈值扔 RankIC 低者)。入池门:与池内每因子 |corr|<0.7,池≤已挖掘数 50%。
- **防过拟合的严谨点**:RankIC 入池门**只在 2021 验证期算**,**2022-2025 测试窗口在进化/建池期间从不访问**;下游用 LightGBM(~150 因子)。

### 1.3 实验与关键数字(全部"论文声称",来源待核是否真实复现)

- 主结果 CSI300 + GPT-5.2(测试 2022-01~2025-12):**IC 0.0472 / ICIR 0.2691 / RankIC 0.0459 / IR 0.6453 / ARR 4.68% / MDD 11.80%**。
- **含交易成本**(0.20% 往返:买 0.05%+卖 0.15%),TopkDropout 低换手(每次只换 ~10% 持仓)。
- 零样本迁移:C S I 300 挖掘因子 → CSI500 +40.28%、S&P500 +19.1% 四年累计超额(扣不扣成本**未注明**,待核)。
- 基线:ML(LightGBM 等)、DL(GRU/LSTM/Transformer/TRA)、经典库(Alpha158/360)、LLM agent(RD-Agent/AlphaAgent,各配 5 backbone)。**未对比 GP 符号回归基线**。
- 效率:~1.8M token/run,约 20 小时,CPU 即可(无本地 GPU 依赖)。
- 收敛:约 11-12 迭代 / ~350 因子为最优;之后冗余因子反伤稳健性。

### 1.4 ⚠️ 审慎信号(务必不可省略)

- arXiv 2026 日期 + **当时并不存在的模型名**(GPT-5.2、Claude-4.5-Sonnet)+ **无独立 Limitations 章节** → 有"未来合成/推演设定"的痕迹。
- 结论:**数字在 PDF 里逐字存在**(agent 已核实),但"是否为真实可复现的实验结果"→ **来源待核**。因此:
  - **不要把它当"已验证因子库"来参考具体因子**(它挖掘出的 `Institutional_Momentum_Score_20D` 等因子的超额是论文声明)。
  - 但**方法框架(轨迹进化、一致性门控、拥挤控制、验证期分离)**本身是有信息量的思路,与论文数字的真实性可分离取用。

## 四、核心张力:你的"逻辑驱动为主"vs 它的"进化挖掘为主"

这是本文最值得你拍板的一点。

- **你现有立场**(来自 `量化工程调研.md`):主流是"逻辑驱动为主、数据挖掘为辅";数据挖掘有三大硬伤(过拟合、不可解释、不可归因),只做局部增强,**不负责发现新假设**。
- **QuantaAlpha 立场**:LLM 进化驱动的挖掘为主,声称能发现"结构性因子"(如 *Mean-Reverting Range Deviation*、*Overnight Gap Structure*),并靠因子语义多样性被动应对 regime shift。

**我的评估判断(不是事实)**:这两者**不必二选一**。你的伪装诊断早已证明——暴搜来的强 IC 因子大半是价位/规模伪装。QuantaAlpha 的"被动多样性"并不能解决这个根本问题(它的 2023 案例里,自己重写的 Drawdown_Gated 等因子在风格轮动下也反转了)。所以:

> **正确姿势是把 QuantaAlpha 的挖掘卡进你漏斗的第 2.5 步**:让 LLM 批量产"候选假设/因子表达式",然后全部走你已有的门1-4 + 伪装诊断。挖掘承担海选,你承担"审美+证伪"。它解决不了你伪装诊断要解决的问题,你的漏斗反而能挡住它最脆弱的部分。

这个判断直接落到第五节的方案上。

## 五、可落地的最小方案(如果要做)

按投入从低到高,三条路(均不改核心架构,复用你已就位的接口):

**路径 A — 纯思路/流程(最低成本,推荐先做)**
用 LLM 当"批量候选生成器"跑通一次你的门1-4:
1. 你给方向/种子(如"量价时序相关族里,还有哪些与现有11因子正交的形态")
2. LLM 产 N 个候选因子定义(继承 `FactorBase` 的接口描述,不直接生成代码)
3. 人工快速筛→实现→走现有 `verify_ic_parallel.py` / corr_diag / 门2-4
4. 产出:明确"LLM 海选 vs 你验证"的边界,不把模型输出当已验证因子
> 对应你已确认的"把 agent 当工程执行/移植/验证自动化工具",只是范围扩到"提候选假设"。

**路径 B — 半自动挖掘(中成本)**
在 A 基础上加一层:**轨迹/候选池记忆**(保留"哪些假设被门2-4 烧掉了"作为反馈),让 LLM 下一轮避免重复——这正是 QuantaAlpha 交叉"继承已验证血统"的轻量版,不必真做染色体。

**路径 C — 复刻 QuantaAlpha(高成本,不推荐)**
全流程(轨迹进化+AST 一致性+拥挤控制+Qlib)复现。**不建议**:开销 ~1.8M token/20h/run、需引入 Qlib 二进制、且论文数字来源待核。除非你后续专门想做出这个方向的玩具,否则跳过。

**无论哪条,保留铁律**:LLM 生成过程不得接触测试期数据;所有产出先过伪装诊断;论文宣称的业绩一律来源待核。
