## 一、A 股 T+1 超短线"量化筛选 + AI 裁决"系统全流程拆解(来源:Big-A-chovy)

> **来源**:GitHub 项目 [LuQTest/Big-A-chovy](https://github.com/LuQTest/Big-A-chovy)(本地路径 `/home/cambricon/Documents/code/Big-A-chovy`,基于 v0.5.0-preview.3 源码)。
> **拆解时间**:2026-09-24。拆解基于实读该项目全部核心文档(`AGENTS.md`、`README.md`、`选股框架.md`、`CLAUDE.md`、`skills/盘中/SKILL.md`、`daily-stock-analysis/references/screeners.md`)与关键源码(`tools/rule_config.py` 全部阈值、`daily-stock-analysis/scripts/a_share_daily_screen.py` 的 `main()` 执行顺序及交集/突破/资金三个状态机函数)。
> **数据源备注**:该项目 README 顶部声明行情数据接口目前访问受限,现版本可能无法正常拉取行情;本文拆解的是策略逻辑本身,与数据源可用性无关。
> **边界**:本文是该项目设计逻辑的拆解笔记,不构成任何投资建议。

### 1.0 系统定位

A 股 T+1 超短线(低吸模式)量化筛选 + AI 辅助决策工作台。核心分工:**机器负责"发现候选",AI 按规则"裁决",人负责"下单"**,全链路不自动交易。

最特别的设计是严格的分层权威链(冲突时以上层为准):

| 层级 | 文件/目录 | 职责 |
|---|---|---|
| 入口 | `AGENTS.md` | 所有 AI 助手统一入口,只管定位与红线 |
| 规则权威 | `选股框架.md` | 交易规则唯一来源:信号层级、一票否决、参数总表、实验权限 |
| 工作流 | `CLAUDE.md` | 盘中三模式(决策/盘问/复盘)、`ggp` 快捷流程、沟通约定 |
| 执行入口 | `skills/盘中/SKILL.md` | 唯一执行脚本 |
| 发现层 | `daily-stock-analysis/` | 筛选引擎 + GUI + 实时看板 + Web 工作台,输出只是候选 |
| 辅助 | `tools/` | 报告扫描、行情/基本面查询、影子验证(全部非权威) |
| 事实来源 | `决策记录/YYYYMMDD.md` | 持仓、观察池、T+1 预案的唯一记录(本地私有) |

`tools/rule_config.py` 是"共享机器参数注册表"——所有脚本的可执行阈值从这里读,语义权威仍在框架;改参数必须同步框架参数总表并跑 `validate_consistency.py` 对账。

### 1.1 总览:一条快照的生命周期

```
拉行情 → 体检 → 预筛 → 逐股增强 → 资金增量 → 分池 → 公告门禁 → 资金优选 → 状态机 → 报告落盘
   │        │       │        │          │        │        │           │          │
 数据层   市场环境  省资源   指标计算    连续性   候选发现   一票否决    排序放大    信号成熟度
```

看板模式(`realtime_engine`)每 1–2 分钟把这条流水线跑一遍,每遍产出一份报告;**跨快照的记忆**(资金历史、交集状态、观察池状态)持久化在三个 JSON 里(`flow_snapshot.json` / `intersection_state.json` / `watchlist_breakout_state.json`),这是状态机能工作的前提。

### 1.2 阶段 1:数据获取与市场体检

| 步骤 | 做什么 | 细节 |
|---|---|---|
| 1.1 | 网络择优 | `network_path.py` 并发实测直连/候选代理/环境代理,选最快路径(粘性 50ms 防抖动,连败 3 次熔断 60s) |
| 1.2 | 拉全市场快照 | 东财 push2 分页拉约 5000+ 只;失败降级新浪(**降级模式字段缺失:超短池/交集/资金优选/低吸买点全部不输出**,趋势池仅供观察) |
| 1.3 | 拉指数 + 板块指数 | 上证/深成/创业板 + 东财行业板块行情 |
| 1.4 | 市场宽度体检 | `market_summary`:涨/跌/平家数、涨跌停数、上涨占比(breadth)。**同时做数据质量自检**:涨跌幅缺失>10%、下跌数为 0(疑似只拿到涨幅榜)、页数不完整 → 标记 `degraded`,共振判定停用 |
| 1.5 | 板块统计 | `sector_stats`:每个行业内的强势股数、平均涨幅——后面共振判定的事实基础 |

### 1.3 阶段 2:预筛与逐股增强

| 步骤 | 做什么 | 细节 |
|---|---|---|
| 2.1 | 预筛 | 只保留**涨幅 1%–6.5%** 的票进后续流程(几百只),不给全市场拉K线 |
| 2.2 | K线增强 | 并发拉 90 根日K → MA5/10/20、昨日 MA20(判斜率)、5 日累计涨幅、距 60 日高点、今日量能 vs 5 日均量 |
| 2.3 | 分时增强 | 拉 1 分钟线 → VWAP 均价线、价格是否站上、距 VWAP 距离 |
| 2.4 | 资金流字段 | 主力/超大单/大单/中单/小单净额、主力净占比(净额/成交额) |

### 1.4 阶段 3:资金连续性(跨快照记忆的核心)

| 步骤 | 做什么 | 细节 |
|---|---|---|
| 3.1 | 读历史 | `flow_snapshot.json` 保留**约 30 分钟**的资金快照 |
| 3.2 | 算增量 | 5 分钟增量 = 当前主力净额 − 约 5 分钟前快照(3–7 分钟窗口内取最接近的);15 分钟同理 |
| 3.3 | 量能差分 | 同源算 5 分钟成交额/量增量、相对历史均量倍数(不额外发请求) |
| 3.4 | 算主买比 | `buy_ratio = (100+主力占比)/(100−主力占比)`,超大单+大单为正且 5 分钟增量>0 时加冲量项(上限 +0.5) |
| 3.5 | 流向五分类 | `classify_flow`:**有效流入**(主力正+大小单同向+价涨+VWAP上)/ 疑似流入 / **价量背离**(资金进但价不涨或 VWAP 下)/ **疑似派发**(小单进+大单出+高位)/ 数据不足 |
| 3.6 | 存快照 | 当前数据写回,供下一轮差分 |

### 1.5 阶段 4:分池(静态硬条件 + 分类打分)

| 步骤 | 做什么 | 关键条件 |
|---|---|---|
| 4.1 | **严格超短池** | 涨幅 2–5.5%、距盘中高点≤3%、换手>3%、量比>1.2、成交额>3亿、价>MA5、5日涨幅≤18%(价 5–30 元、市值<200亿) |
| 4.2 | **趋势观察池** | 均线修复中(允许 MA5 略低于 MA10×98.5%)、涨幅 −1%~4.5%——**还没确认,先盯着** |
| 4.3 | **趋势确认池** | 价>MA5/10/20 且 MA20 上升、涨幅 3–6.5%、距60日高≤10%、量能≤5日均量2倍 |
| 4.4 | **双池交集** | 超短池 ∩ 放宽版趋势确认——核心信号的原料 |
| 4.5 | **低吸超短/低吸趋势** | 先过排除(硬黑名单 + 高位派发:5日涨幅≥12% 且近 6 快照中≥3 次主力为负),再分 A(可买区)/B(观察)/C(禁追)+ 打反追高标签 + 评分排序 |
| 4.6 | **主导标签** | `absolute`(超单>0 且占主力≥50%)或 `coalition`(仅实验)或 ✗ |
| 4.7 | **低开洗盘识别** | 低开≥2% + 盘中翻红站上均价线 + 当日及 20 日主力净流入>0 → 仅进观察 |

低吸池的反追高风险标签:距高点<0.3pct → 追高风险、回落>1.5pct → 冲高回落、14:20后涨幅>4.8% → 尾盘追高、换手>10%且滞涨 → 巨量滞涨。低吸池排序按"可交易性"而非涨幅:止损距离、VWAP贴合、板块共振、换手适中度排在裸涨幅前面。

### 1.6 阶段 5:公告门禁(fail-closed)

| 步骤 | 做什么 | 细节 |
|---|---|---|
| 5.1 | 查公告 | 对所有池内股票并发拉最近公告,关键词分级:hard(减持/立案/预亏…)→ `avoid`;watch(质押/担保…)→ `watch_risk`;带缓存 |
| 5.2 | 池门槛 | `apply_announcement_pool_gates`:**avoid/unknown 直接从各池剔除**(缺数据按 unknown 处理,宁可错杀) |
| 5.3 | 汇总 risk_map | 公告查询结果是唯一权威,其它字段只补缺、缺了按 unknown——所有下游模块(交集、突破、资金优选)读同一份 |

### 1.7 阶段 6:主力资金优选(排序放大镜)

| 步骤 | 做什么 | 细节 |
|---|---|---|
| 6.1 | 圈候选 | 严格超短+趋势观察池中排除 avoid/unknown 的票 |
| 6.2 | 算资金评分 | 主力净占比 35 分 + 超大单占比 20 分 + **持续性** 20 分(5分钟增量/成交额)+ 价格确认 15 分(VWAP上+上涨)+ 共振 10 分;惩罚:疑似派发 −35、价量背离 −20、主力净流出 −20、回落过大扣 15 |
| 6.3 | 分级 | **A≥70 / B 40–69 / C<40** |
| 6.4 | sector_boost | 板块锚点(成交>20亿+超单主导+回落<2%)+ 共振≥3 → 个股 clean+主力>5%+VWAP上 → +15 分(实验,加分不替代硬门槛) |
| 6.5 | 再过一遍门禁 | 派生池重新走 5.2,防止 avoid 靠重排复活 |

### 1.8 阶段 7:明日观察池 + 突破状态机

| 步骤 | 做什么 | 细节 |
|---|---|---|
| 7.1 | 建池 | 有共振 + 均线修复 + 涨幅<5.2% + 5日涨幅≤12% 的票,每只算四个价位:**触发价**(前高)、**买区**(MA5/MA10 的 99.5%–101%)、**失效位**(MA10×98.5% 与前低取低)、**追高禁区**(触发价×1.025 以上) |
| 7.2 | 突破状态机 | 次日跟踪:`WATCHING → TRIGGERED(触价) → CONFIRMED(2快照站稳) → B_BREAKOUT → A_STRICT(还须资金评分≥70)`;09:30–09:40 只观察不许升级;跌回触发价/超追高禁区/5分钟转负 → **立即降级重置**;跨日自动合并昨日标的(保留触发价,清零确认数) |
| 7.3 | 持久化 | `watchlist_breakout_state.json` |

### 1.9 阶段 8:双池交集状态机(信号成熟度)

| 步骤 | 做什么 | 细节 |
|---|---|---|
| 8.1 | 准交集预警 | 超短池里、距趋势确认池 10 项质量条件**恰好差 1 项**、且三道前置门槛(主力净额>0、5分钟增量>0、VWAP上方)全过的票 → 标"准交集",并预测差项的触发价 |
| 8.2 | 状态机推进 | `OBSERVING → 准交集 → 锁存(15分钟) → 等回踩(0.5–1.5%) → 回踩确认(量比萎缩≤0.7+VWAP守住+5分钟资金不转负,2快照) → ENTRY_ELIGIBLE` |
| 8.3 | 硬约束 | **每快照最多前进一级**(禁止跳级);同一 snapshot_id 不重复计数;首次交集时已过热(涨幅>4.5%或换手>8%)→ 只能 LATE_INTERSECTION;公告非 clean / 过 14:20 / 市场 CASH → 不给 ENTRY_ELIGIBLE |
| 8.4 | 持久化 | `intersection_state.json`,次日清零重来 |

### 1.10 阶段 9:输出

- 组装 result(含 meta:时间戳、交易状态、数据源、是否降级、各环节耗时)→ `render_markdown` 生成报告 / JSON → 存 `筛选结果/YYYYMMDD/A股筛选结果_HHMM.md`
- 报告包含:市场宽度 → 指数 → 各池表格(超短/趋势观察/趋势确认/交集/准交集及状态/资金优选/低吸ABC/低开洗盘/观察池及突破状态)→ 数据质量警告

### 1.11 阶段 10:决策层(盘中 skill,报告之后)

1. **恢复状态**:读最新 `决策记录` → 三类持仓(真实/模拟/解套)、现金、在盯清单、T+1 可卖(`get_position.py`)
2. **圈报告范围**:上次提问到当前的**全部**快照(不能只看最新一份)
3. **先核旧再查新**:先看在盯/持仓的状态变化,再扫新候选
4. **逐项门禁核验**:公告 clean、超大单>0、资金连续性(连续 3 快照衰减即作废)、主导 absolute、板块共振、买点(VWAP±0.1%、回落<1.0%)、**分笔五档承接(主买比>1.5)**、基本面(EPS>0、动态 PE>0、YTD)、时间窗
5. **四层裁决**:①真实仓可开仓(须七项支撑+买点+止损+T+1计划)②模拟仓可买(注明实验类别)③仅观察/暂不开(写明卡点)④完全空仓
6. **落盘**:按统一格式写入决策记录,更新观察池
7. **复盘**:收盘核算盈亏、更新持仓快照、维护 T+1 计划

其中"七项支撑"指每个真实仓建议必须展示:①板块主线/共振/地位 ②主力资金与超大单主导证据 ③分笔主动成交、五档承接与主买比 ④买点与 VWAP 贴合度 ⑤盈利/EPS/动态PE/YTD 及数据时点 ⑥模拟验证状态 ⑦买点区间、止损、止盈、盈亏比和 T+1 计划。

### 1.12 贯穿性机制:每个环节在防什么错

| 机制 | 防的错误 |
|---|---|
| 预筛涨幅 1–6.5% | 浪费资源给不可能买的票 |
| 降级模式关掉大半池子 | 字段缺失被当成"数据正常"误判 |
| 宽度自检(degraded → 共振停用) | 半截数据算出假共振 |
| 5/15 分钟增量而非瞬时值 | 单点资金脉冲被当成持续流入 |
| "疑似派发"标签(小单进大单出+高位) | 散户接盘被当成主力进场 |
| 超大单为负一票否决 | 主力净占比>5% 但结构是散户堆量 |
| 状态机禁跳级 + 2 快照确认 | 瞬时共振/单快照噪声直接触发买入 |
| 回踩确认(量萎缩+VWAP守+资金不转负) | 交集出现即追在脉冲顶点 |
| 追高禁区 ×1.025、距高点≤3% | 突破追在高点 |
| 公告 fail-closed(unknown=avoid 级) | 公告没查到就当 clean |
| 14:20 停新仓 | 尾盘信号没有次日验证时间 |
| 决策记录为持仓唯一来源 | 从历史会话/记忆猜当前持仓 |

另有两套贯穿机制:

- **时间窗口**(`rule_config.py` 的 `execution.time_windows`):09:30–09:40 观察禁买 → 09:40–09:50 等待确认 → 09:50–10:45 第一买点 → 10:45–11:30 早盘确认 → 午休 → 13:00–13:45 午后回流(仓位减半)→ 13:45–14:20 午后尾段 → 14:20–14:40 尾盘禁新仓 → 14:40 后仅持仓管理。
- **实验影子验证**:框架登记 9 个待验证项,其中 4 类(coalition 合力、观察池突破、sector_boost、龙头分歧)走"影子采样 → T+1 结算 → 满 20 个完整结算样本 + 评估 → 才考虑转正"的流程,转正前一律只允许模拟仓。完整结算要求 `checked=true`、`extremes_complete=true`、日K匹配成功,最大浮盈/最大回撤/假突破全部核算,否则不计入样本数。

### 1.13 一句话总结

整套系统的设计哲学:**每一步都在把"看起来能买"往"持续强、结构真、还买得到、且在允许的时间窗内"收敛,任何一环证据不足就降级或否决,绝不向上补猜**。状态机和多重门槛把"看起来强"过滤成"持续强且还能买",资金主导标签区分真主力和散户堆量,VWAP/回踩约束买点,宁可错过不给追高。

## 二、策略评估:哪些合理,哪些有问题(来源:Big-A-chovy)

> **评估对象**:第一章所述系统的设计与逻辑,不是历史绩效。
> **评估边界**:本地克隆不含 `决策记录/`、`筛选结果/` 与影子样本库(私有数据,已被排除),实际胜率与盈亏无法核验。本章全部结论针对规则设计本身。
> **评估时间**:2026-09-24。
> **结论摘要**:"流程可信"不等于"边际优势(edge)可信"。该系统的工程纪律与风控自洽性优于绝大多数个人系统;但承载真实仓的核心信号缺少统计验证,盈亏结构对胜率要求苛刻,参数依赖个案拟合。

### 2.1 合理的部分

**治理与工程**

| 机制 | 评价 |
|---|---|
| 权威链 + `rule_config.py` 单一参数源 + 一致性对账 | 规则漂移是演化型系统的主要失效方式,该设计从结构上消除它 |
| fail-closed:公告 unknown 按 avoid 处理,数据降级时关闭大部分候选池 | 数据缺失一律按坏数据处理,方向正确 |
| 市场宽度自检:下跌数为零视为数据不完整,停用共振判定 | 防"半截样本算出假共振" |
| 状态机禁跳级 + snapshot_id 去重 | 防单快照噪声与同一份数据重复计数 |

**风控与执行**

- **T+1 约束建模正确**:当日买入不可卖、次日开盘风险优先退出、09:45 常规退出截止。多数散户系统默认可以当日止损,该系统没有犯这个错误。
- **绝不补仓、单股上限 1/4 仓位、默认试错仓 1/40**:硬性阻断"亏损加仓"这一主要爆仓路径。
- **回落基准锁定**:首次通过全部门槛时锁定回落基准,之后不重新分档。阻断"移动球门"式的自我合理化——对交易心理失败模式的显式编码,少见。
- **信号衰减规则**:连续 3 快照主力衰减且 5 分钟增量转负即作废,重现后重新核验。这是信号新鲜度检查。
- **14:20 后停止新开仓**:尾盘信号缺乏次日验证时间,与 T+1 执行约束自洽。

**信号用法**

- **回踩确认入场**(回落 0.5–1.5% + 量能萎缩 + VWAP 守住 + 资金不转负):经典动量延续买法,条件组合自洽。
- **用 5/15 分钟资金增量而非累计净流入**:累计值与"价格已上涨"高度共线,增量才携带边际信息。这是资金流用法的关键分界。
- **超大单为负一票否决**(即使主力净占比达标):结构校验,防"大单堆积的假主力"。
- **疑似派发标签**(小单净流入 + 大单净流出 + 高位):对散户接盘形态的有效识别。
- **板块共振 ≥2 只 + 市场环境 CASH 闸门**:A 股短线动量由板块驱动,方向正确。
- **基本面盈利门禁**(EPS>0、动态 PE>0):对真实仓而言粗糙但合格的防御。

**对 AI 裁决的约束**

"预测≠规则"、四层强制输出、机器通道强制 JSON、缺失值用 null 不猜值:将 LLM 限制在规则应用而非预测,是对 LLM 的正确用法。

### 2.2 有问题的部分(按严重度排序)

**① 盈亏结构与隔夜跳空(最核心)**

止盈 +2%、止损 −3~4%,而 T+1 制度下止损只能在次日执行:

- 买入日盘中下杀无法处理,只能持仓过夜;
- 次日跳空低开时止损名存实亡,实际成交在开盘价;
- 09:45 强制退出同时截断右尾:+2% 即兑现,盈利不延续。

名义盈亏比要求胜率超过 60–67% 才能打平(3/(3+2) 至 4/(4+2)),尚未计入交易成本与跳空滑点。系统真实收益分布 = 名义止盈/止损 + 一个未被控制的隔夜跳空左尾(左尾指亏损一侧的极端值)。该结构能否生存,取决于"回踩确认的强势股次日早盘溢价"这一条件期望是否足够高,而框架中没有对该期望的任何测量。

**② 方法论倒挂:实验信号有验证,生产核心没有**

框架要求实验信号(coalition、观察池突破、板块加分器等)积累 20 个完整结算样本并评估后才可转正,方法论正确。但承载真实仓的核心信号(双池交集 ENTRY_ELIGIBLE)在公开工件中没有对应的统计验证记录,参数状态为"已固化",依据是个案教训而非收益分布。最需要验证的信号恰是唯一免检的。

**③ 20 个样本统计效力不足**

区分 55% 胜率与 50% 需要数百样本。20 个样本下噪声容易呈现为优势:20 次抛硬币出现 13 胜 7 败的概率约 7%。作为"启动转正讨论"的门槛可以,作为转正依据太薄。

**④ 参数由个案拟合,非统计估计**

参数表的调整原因均为具名案例:哈药股份→板块联动≥2、中宠→信号衰减、大恒科技→回落分档、兴森 vs 北方稀土→资金排序优先、煤炭双涨停→C 类≥3 只、兴业银锡→分笔五档前置。每个补丁局部合理,整体是路径依赖的规则堆积,对 2026 年 7–9 月这一特定市场阶段存在过拟合风险。规则冷却机制只约束实验信号,生产参数可以即时修改。

**⑤ 资金流是供应商代理指标**

东方财富的订单大小分类是推断值而非真实对手方:拆单、算法交易、对倒均可污染。主导标签、一票否决、资金评分全部建立在该代理指标上,信号质量上限被数据源锁定。框架待验证项①("盘口大卖单≠真抛压")说明作者已意识到此类问题。

**⑥ 带状阈值的伪精度**

低吸 A 类"涨幅 2.2–4.6%、量比 1.2–3.8、换手 2.5–8%":该精度的边界没有证据支持 2.2 优于 2.0。作为模糊先验可用,作为硬门槛是假精度。

**⑦ 规则复杂度超过验证能力**

嵌套状态机 × 权限分层 × 时间窗 × 实验例外的组合空间,一致性检查只对齐"文档 vs 代码 vs 影子库",不检查规则交互是否仍符合设计意图。单模块有单元测试,但复合条件(如"准交集恰好差一项")的边界情况随规则增厚而组合增长。

**⑧ LLM 裁决缺少闭环审计**

输出 schema、框架引用、四层强制输出降低了非确定性,但未消除。没有对"LLM 裁决与规则预期一致率"的系统化抽检;复盘为人工,规模受限。

**⑨ 交易成本未建模**

佣金 + 印花税 + 过户费 + 滑点,往返约 0.1–0.15%,占 +2% 止盈目标的 5–8%。框架全文未提成本,盈亏比核算处于无摩擦假设下。

### 2.3 改进建议(按优先级)

1. **为核心信号建立影子结算**:将 ENTRY_ELIGIBLE 入场纳入影子库,统计"入场价→次日 09:45 实际收益"的完整分布:胜率、期望、左尾分位数(P5/P10)、跳空低开频率。这一个数字回答整套系统是否成立。
2. **把 +2%/−3~4% 当作假设而非纪律**:用历史快照回放(`replay_intersection_20260728.py` 已有雏形)测试不同止盈/退出截止组合的条件期望,让参数来自分布而非案例。
3. **样本门槛分级**:20 个样本只允许统计观察,50 个允许讨论,100 个以上或通过序贯检验才考虑转正。
4. **成本进核算**:盈亏比公式加入约 0.15% 摩擦项。
5. **带宽敏感性检查**:对带状阈值做 ±20% 扰动,结论不稳定的参数降级为模糊先验。
6. **生产参数设冷却期**:个案教训先记为待验证,冷却若干交易日后决定是否修改生产规则——把实验纪律反向应用于核心参数。

### 2.4 结论

该系统作为**纪律执行器**是优秀的:其最大价值可能不是选出更好的股票,而是强制执行了不补仓、不追高、限时退出这些多数人做不到的行为约束。作为**策略**,其边际优势是断言的、未测量的;盈亏结构容错率低,而最需要的统计量——核心信号的条件收益分布——恰好缺失。优先执行建议 1,拿到该数字后再评估其余。

## 三、筛选策略的因子化拆解(来源:Big-A-chovy)

> **目标**:将该系统的筛选逻辑重构为可单独检验的因子。公式与代码实现一一对应(`low_ultra_class`、`low_trend_class`、`rank_capital_candidates`、`classify_flow`、`build_watchlist` 及 `rule_config.py` 阈值),非近似改写。
> **产出**:46 个单因子(M/V/F/S/E/G 六系列)+ 4 个代码原生复合因子(C 系列)。
> **符号约定**:`chg` 当日涨幅(%);`turnover` 换手率(%);`amount` 当日成交额(元);`main_net / super_net / big_net / small_net` 主力/超大单/大单/小单净额;`vwap` 分时均价;`MA5/10/20` 对应周期均线;下标 `t−5m` 表示约 5 分钟前的快照值;`[P]` 表示条件 P 成立时取 1,否则取 0。

### 3.1 方法论前提

该系统的因子与常规多因子框架有三个结构性差异,直接决定检验工具的选择:

1. **多数因子是带状的(倒 U 型),不是单调的**。"涨幅 2.2–4.6%、换手 2.5–8%"的含义是中间最好,不是越大越好。用原始值做 IC(信息系数:因子值与后续收益的截面相关系数)或分层回测会得到错误结论,必须先中心化:`x* = −|x − x_target|`,即到理想值的负距离。代码内的打分函数已是该形式,本章直接提取。
2. **截面极小**。盘中任一时点合格标的仅数只至数十只,截面 IC 无统计意义。合适的工具是汇总事件研究(pooled event study):统计因子条件下的 T+1 09:45 收益分布。
3. **资金流因子是代理口径**。主力/超大单等字段来自数据供应商的订单大小推断,跨源不可比,可被拆单污染。这是 F 系列的地基风险,因子定义本身无法解决。

```
      + [MA5 贴合≤3.5%]×10 或 4          # M10
```

**C3 低吸趋势评分 LOW_TREND_SCORE**(满分 110,`low_trend_class`):与 C2 同构,差异为涨幅峰值 3.8(scale 7)、换手改区间判分([2, 7.5]→20,否则 6)、成交额好区间为 4–15 亿,并增加两个组件:均线斜率([MA5↑∧MA10 平或升]→15,否则 3)与 MA20 乖离(`max(0, 15 − 乖离×100)`)。

**C4 观察池评分 WL_SCORE**(`build_watchlist`):

```
score = 100 − |chg−3.2|×8 − max(0, five_ret×100−8)×2 − max(0, dist60×100−8)
```

### 3.9 检验路线

1. **母假设优先**:对 E3(状态机阶段 = ENTRY_ELIGIBLE)做事件研究,统计条件收益分布(入场价→次日 09:45),含左尾分位数。这是整套系统的母假设,对应第二章建议 1。
2. **单因子增量检验**:在 E3 条件下,逐个检验 M/V/F/S 因子能否进一步区分好坏样本(条件分层或 logistic 回归)。无法提供增量信息的因子即冗余。预期 M3/M4/M5(三种上限型动量)高度共线,V1/V2/V3 亦然。
3. **带状因子先中心化**:全部以 `−|x − target|` 形式进入模型,不用原始值。
4. **F 系列双源对照**:同一时点用第二个数据源重算资金流因子,检验结论是否翻转,直接量化代理指标风险。
5. **按日聚类**:同日多标的共享市场与板块状态,不是独立样本;检验需按日聚类或按日去均值。

### 3.10 预判(判断,非事实)

基于因子结构本身的推断,待检验:

- **可能有独立信息量**:F4/F7(资金加速度与衰减)、M2/M6(高点回落与 VWAP 偏离)、S1/S2(板块共振)。
- **更接近"风格定义"而非"收益预测"**:M1/V3/V4 等带状因子——它们定义"什么是可买的形态",但对形态内部的优劣排序能力存疑。
- **E3 是全部因子的复合终点**,其有效性即第二章指出的缺失统计量。因子化拆解的意义在于:若 E3 整体无效,单因子检验可以定位失效来自哪一层。
