## 一、调研:机构怎么用 ML,验证纪律长什么样

### 1.1 主流格局是怎么形成的

中低频量化选股里"信号层用 GBDT、风险层用线性"这个格局不是设计出来的,是被数据特性逼出来的。分三个阶段:

**阶段一(1970s–1990s):线性统治。** BARRA 线性多因子风险模型、APT、Fama-French 三因子。线性统治不是因为它够好,而是当时的算力和数据只支撑线性。更根本的原因:金融数据的信噪比极低——好的截面因子 IC(因子值与下期收益的截面相关系数)通常只有 0.02–0.05,月频选股模型的整体 R² 只有 1–2%。这样的数据只养得起几十个有效参数,线性模型已经是数据承载力的上限,更复杂的模型在噪声里学到的是噪声。

**阶段二(2016 年前后):ML 系统性入场。** Gu-Kelly-Xiu(2020,数据为美股 1957–2016 月频)第一次用统一框架对比各类模型:线性模型样本外 R² 约 0.2%,最好的神经网络约 0.4%。两个信息:非线性**有**增量;但增量是"翻倍、绝对值仍然很小"——pp(百分点)级别的改进。

**阶段三(2020s 至今):GBDT 成为中频截面信号合成的事实标准。** 原因:①表格型因子数据上树模型稳定强于深度网络(ML 界反复复现的结论,Grinsztajn et al. 2022);②天然处理缺失值、非线性阈值、因子交互;③保守调参下行为可靠、失败模式温和。深度学习的位置在另类数据(NLP 舆情、高频微观结构)和端到端执行,不在"几百个表格因子怎么加权"。

**对验证纪律的含义**:既然 ML 的真实增量本来就是 pp 级,那验证协议也必须是 pp 级——+0.5pp 的"改进"完全可能是单次 seed 抽样运气或多轮尝试后的选择偏差。这是本计划全部步骤的共同动机。

### 1.2 为什么恰好按层分工:错误的不对称性

机构的典型技术栈是三层,每层的模型选择由**该层犯错的代价**决定,而不是由"哪个模型更新"决定:

| 层 | 机构主流 | 为什么 | 错误的性质 |
|---|---|---|---|
| 信号层(预测收益) | GBDT(LightGBM/XGBoost) | 灵活性收益全部保留 | **软错误**:排名差一点 → IC 低一点,仓位还是那些仓位,不会爆仓 |
| 风险层(预测协方差) | 线性多因子(BARRA CNE6/Axioma 一系) | 协方差要进优化器,必须正定、稳定、可解释;非线性风险模型在这些工程性质上全面劣于线性 | **硬错误**:协方差估错 → 优化器把杠杆压在错误的地方,损失被杠杆放大且无界 |
| 组合层(构造持仓) | 优化器(mean-variance/BL/risk parity) | 数学形式本身是凸二次规划 | 不存在"用不用 ML"的问题 |

一句话:**预测端可以激进,因为损失有界;风险端必须保守,因为损失无界。**

A 股按产品形态的具体化:公募指增在跟踪误差约束下增强,线性+优化器为主干(约束把问题拉回线性),ML 信号在约束内叠加;私募量化多头 GBDT 信号自由度最大,所以渠道尽调都在问风格暴露;市场中性 = GBDT 信号 + 线性对冲(股指期货中和 beta),信号激进、对冲保守,与上表分层逻辑一致。

**junior_quant 对照**(实读代码):信号层 = `factors/composite.py`(线性 ic)与 `factors/composite_ml.py`(GBDT)可切;风险层 = `risk/manager.py`(标量止损 + 个股滚动波动率仓位乘数,无因子风险模型);组合层 = top_n 选股 + 换手 buffer。形态是机构栈的微缩,**最薄的是风险层**——没有因子级风险模型,只有标量波动率目标。这决定了它暂时回答不了"超额收益里有多少是小盘暴露、多少是残差 alpha"(对应第五步)。

### 1.3 "线性打底 + ML 补增量"的三种工程形态

这不是一句口号,是三种边界明确的工程形态,区别在于**ML 被允许碰什么、错了损失多大**:

**形态 A:门控切换(全有或全无)。** 两条完整生产管道只差一个合成器开关;决策门在跑回测**之前**写死(预注册),全过才翻。优点:生产永远只有一条路径。代价:翻门是离散大动作,且一次翻门后没有机制保证 ML 持续合格——**必须配季度复验 + 失败回退**,否则翻门就是一次性豁免。

**形态 B:分数融合(按比例共存)。** `final = (1−w)·z(linear) + w·z(ml)`,z() 为截面标准化。三个关键细节:①w 本身是超参数,在同一份历史上反复试 w 挑最好与挑树深度是同一种过拟合——约束做法是 w 只走 0.25→0.5→0.75 整数档,每升一档过一次完整 walk-forward,**降档不需要验证**(棘轮原则:收紧即时,放宽要证据);②两个分数相关性 <1,混合分数更平滑,边际换手天然下降,对成本敏感的策略是免费收益;③账目可分,季报能写成"底座贡献 +X%,ML 增量 +Y%"。

**形态 C:环节分工(ML 只碰有界子问题)。** 四个子形态,共同点是 ML 错了的损失有上限:

| 子形态 | ML 管什么 | 错了的损失上限 |
|---|---|---|
| 执行时点 | 预测明日开盘/VWAP/收盘哪个成交价更好 | 几十个 bp 执行价差 |
| 仓位微调 | 线性定排名,ML 在基础权重 ±X% 内调 | 构造性有界 |
| 否决过滤 | 只预测"线性选中的哪只会跑输",只能删不能加 | 少赚,不会错买 |
| 特征工厂 | 消化线性吃不下的数据(文本/高频/另类),压缩成 1 个因子喂回线性合成 | 错误被线性框架稀释 |

一句话:A 是换司机,B 是两位司机按比例共驾,C 是 ML 只当导航或传感器。机构最常用的增量路径是 C-特征工厂。

**三种形态共用的账本:增量归因协议。** 不管选哪种,每次调仓同时算三个影子组合(linear-only / ml-only / 实际),记三个数:①排名重叠度(两套分数的 Spearman);②ml-only − linear-only 的区间收益差;③实际组合 vs 两者。解读:重叠 >0.9 → ML 是"昂贵的线性",冗余;重叠低 + 增量为负 → ML 在拟合噪声;重叠中等(0.4–0.7)+ 增量稳定为正 → 甜点区。"补增量"的**增量**必须是这个协议量出来的数,不是感觉。

**junior_quant 对照**:`compare_ml.py` + `config.yaml` weighting 即形态 A;`intraday_filter`(选股层选出 top_n 后二次过滤,只能减不能加,config.yaml:551 起)是形态 C-否决的雏形。差距有二:形态 A 缺复验周期(对应第五步);增量归因只在专门跑的 A/B 里有,未常态化(可选演进,见第六章)。

### 1.4 显式线性基准的完整标准

"能被 ML 挑战的显式线性基准"由三个构成要件 + 一个强度要求定义:

**要件 1:同管道单变量。** 同因子集、同 universe、同 walk-forward 窗口、同成本假设、同换手控制,唯一差异是合成器——差异才能归因到合成层。

**要件 2:持续运行,不是一次性。** 基准是**每次实验的对照组**,不是翻门那一次的道具。任何改动(新因子、新参数、新模型)的评估报告都必须带基准行。

**要件 3:预注册 + 复验。** 翻门标准在看到结果之前写死;翻门后季度复验,失败回退。

**强度要求:基准必须是能找到的最强线性。** 用故意弱的基准(原始因子等权、未标准化的 OLS)打赢 ML 是自欺——弱基准保证 ML 赢。完整阶梯:

```
ic    (启发式线性:ICIR 加权 + 两层正交)        ← 已有,已不算弱
  ↓ 这一段的增量 = "正确处理特征"的收益
ridge (训练型线性:每窗口 RidgeCV,同 purge)     ← 缺的档
  ↓ 这一段的增量 = "非线性"的收益 ←—— 这一段才是 ML 存在的理由
ml    (LightGBM)
```

ml 打赢 ic,可能只是赢在"特征被标准化/正交/正确加权"——这些用 ridge 也能拿到,且 ridge 更简单、更稳、更可解释。**翻门条件应是"打赢 ridge",不只是"打赢 ic"**。每档升档都要 >+1pp/年级别的实质增量,否则奥卡姆剃刀:简单模型赢。

**指标全口径**:超额年化(费后)/夏普/MDD·Calmar/换手与成本/IC 序列(均值、IR、逐窗口衰减)/**负超额窗口占比**。最后一项尤其重要:ML 的典型失败模式不是平均变差,而是"平均赢但输的窗口变多"——方差变大,平均靠几个大赢窗口撑着,这种 ML 上线后会在最需要它的窗口失效。

**junior_quant 对照**:`compare_ml.py` 满足要件 1(docstring 明确"A/B 唯一变量是合成方式")和要件 3 的预注册部分;ic 档含 ICIR 加权 + clamp(floor 0.25/cap 1.50,config.yaml:483-484,防单因子独大)+ 两层正交(config.yaml:269 risk_parity 跨族),已是不弱的基准。差距有三:缺 ridge 档;基准非持续运行(专门 A/B 而非每实验默认动作);无复验周期。

## 三、实施步骤

### 第一步:多种子集成(对应 1.5 #8)

`config.yaml` ml 块:`seed: 42` → `seeds: [42, 7, 2024]`(3 个性价比最高,5 个边际收益递减)。

`backtest/walk_forward.py` `_train_ml_model`(:515 附近):
- 训练循环包一层 `for seed in seeds`,产出模型列表;预测 = 各模型输出均值(回归任务直接平均,保序)。
- `_build_series_caches` 与 seed 无关,只重跑 LGBM fit 段——fit 本身秒级,特征工程段不重复,总成本远小于 3×。
- 退化保护语义不变:任一 seed 退化(best_iter≤1)整体不落盘,保持现有 fail-loud。

`signals/ml_model_store.py`:`save_model_artifact` 从单模型改为模型列表,load 端取均值,meta 记录 seeds。

新增免费诊断(随训练记录,不另跑):种子间预测一致性 = 3 模型两两 Spearman 均值。一致性低 = 模型在拟合噪声——这本身就是健康信号。

**验收**:compare_ml 重跑单 seed vs 3-seed,期望逐窗口 Sharpe 方差收窄。若集成不如单 seed,是模型稳定性红旗,先查根因再继续。

### 第二步:补 ridge 线性基准档(对应 1.4 强度阶梯)

新增 `weighting: "ridge"`:
- `factors/composite_ridge.py`(新):每窗口对与 ML 分支完全相同的标准化因子矩阵(`_build_feature_matrix` 产出,含同 purge)做 RidgeCV,输出截面分数。
- 不做额外特征选择、不差异化预处理——与 ml 分支唯一差别是合成器,保持"A/B 单变量"原则。
- `compare_ml.py` 场景从 2 扩为 3:ic(启发式线性)/ ridge(训练型线性)/ ml。

翻门条件升级(写进 compare_ml.py docstring,预注册):
- 现有:ml > ic 且 >+1pp/年、夏普≥、回撤≤、跨 universe×窗口稳定。
- 增加两条:ml > ridge 且 >+1pp/年;ml 负超额窗口占比 ≤ linear(防"平均赢、输的窗口变多"的方差型失败)。
- 归因逻辑:ic→ridge 的增益 = 正确处理特征的收益;ridge→ml 的增益 = 非线性的收益。后者才是 ML 存在的理由。

可选第四档(低优先):depth-1 GBDT(= GAM,每因子一条阶梯函数、无交互),作 ridge 与全 GBDT 之间的中间档,只在 ml 打赢 ridge 后补测。

### 第三步:试验登记簿 + 简化多重检验折扣(对应 1.1、1.5 #9)

`reports/trial_registry.csv`(新),compare_ml.py(及后续 compare_*)每次场景运行结束追加一行:

```
date, script, config_hash, universe, window, weighting, seeds, 超额年化, sharpe, mdd, 换手, 成本, decision
```

- config_hash = 场景完整 config 的 sha1 前 8 位,防"同配置反复跑挑最好"不自知。
- 新增 `scripts/registry.py`:append + summary(输出试验分布与简化折扣:最优试验须超过全部试验 Sharpe 分布的中位数 + 2σ,否则标注"可能是选择噪声")。
- 历史回填(一次性):既有 `ml_csi1000_*.log` 至少 10 个变体,登记簿首行注明历史试验数 ≥N,使折扣计算诚实。
- 不做完整 Bailey–López de Prado DSR(需预登记预期 Sharpe 与试验相关性矩阵);登记簿 + 分位数门槛是个人系统的够用版本。

**纪律**:登记靠 compare_* 脚本内建 append,不靠人记;绕过脚本手跑的回测不进登记簿,结果不得用于翻门决策。

### 第四步:服务信号滚动 IC 监控——预测力红线(对应 1.5 #10)

现有红线只覆盖可用性(#7 的新鲜度/装配契约)。补预测力:

- `train_ml_daily.py` 每次重训后,追加近 K 个 OOS 窗口的滚动 rank-IC(合成分数 vs 实现的 horizon 收益;walk_forward 已产出同口径 OOS 序列,复用,不算新回测)。
- 阈值:滚动 60 窗口 IC < 历史 OOS IC 分布的 P5 → 触发与新鲜度同级的 fail-loud(或至少 exit 1 + 保留上一份 artifact,镜像现有训练退化语义)。
- 落盘 `reports/signal_health.csv`:重训日期、滚动 IC、P5 阈值、状态。

这是机构"信号衰减自动下线"的个人系统等价物。无实盘阶段,它保护的是"回测依赖的信号在样本外是否还活着"。

### 第五步:暴露归因常规化 + 翻门证据归档与复验周期(对应 1.2、1.3、1.5 #12)

暴露归因(季度):
- 扩展 `analyze_beta_alpha.py` 或新增 `scripts/report_exposure.py`:组合日度超额对 size(流通市值对数)/ beta / 动量 / 波动率风格因子做时序回归,输出"超额年化 = 风格暴露贡献 + 残差 alpha"分解表。
- csi1000 池天然小盘倾斜,compare_ml.py 已记录 size 占比,缺的是收益侧归因——回答"ML 超额有多少只是 size 暴露"。

翻门证据归档(一次,立即做):
- 在 docs/(或 config.yaml 注释)落单一记录:weighting 何时翻 ml、依据哪份 compare_ml 报告、universe×窗口矩阵、四条门逐项数值。

复验周期(持续):
- 季度重跑 compare_ml(ic vs ridge vs 当前生产 ml 配置);任一条不满足 → weighting 回退,直至重新通过。
- 与《全市场选股域迁移计划》联动:其第四步 gate4 本就要全市场重跑 A/B——把"必须带 seeds/ridge/registry"写进该计划验收标准,一次迁移同时完成首次复验。

## 六、后续可选演进(超出本计划,记录备查)

- **形态 B(分数融合)**:第一步 ridge 档落地后再评估;`composite.py`/`composite_ml.py` 都输出截面分数,融合是最小改动路径,但 ml_serving 的 artifact 机制需扩展成持久化两套分数。
- **形态 C-否决的 ML 化**:`intraday_filter` 已是否决过滤的骨架(只能减不能加),把过滤规则从手写阈值换成"预测线性选中的哪只会跑输"的小模型,是有界增量的下一个候选。
- **增量归因协议常态化**:walk_forward 内同时算两套 weighting 的分数并落盘三个数(排名重叠/收益差/实际 vs 两者),使形态 A 也能出"底座贡献 + ML 增量"的季报口径。

## 七、风险与注意

1. 机时:多种子只作用于 LGBM fit 段;RidgeCV 每窗口毫秒级;滚动 IC 复用既有 OOS 序列。总体预计 < 现有单次 compare_ml 的 1.5×。
2. 顺序:第一~三步必须先于《全市场选股域迁移计划》第四步落地,否则迁移重跑的还是弱方法论,结论要再作废一次。
3. ridge 可能打败 ic 使 ic 档变摆设——不是问题,阶梯的意义就是逼每一档证明自己;ic 档保留作最简对照。
4. 登记簿纪律靠脚本内建,不靠人记(见第三步)。
5. 本计划全部针对验证与监控,不改任何交易逻辑(因子、选股、风控参数均不动);形态 B/C 若实施需另立计划。
